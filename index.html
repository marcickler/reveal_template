Part 1

The Setup

Setup

Plain HTML, no build step

  • reveal.js for slides, fragments and speaker notes, fixed 1600×900 canvas
  • css/style.css: Beamer-like look, Latin Modern Sans, colours as CSS variables
  • d3 for charts and animations, KaTeX for all math, also inside SVG
  • Python scripts (uv) turn results into data/*.js
  • Libraries vendored in lib/, so the deck works offline
index.html        slides, one <section> each
css/style.css     look and layout classes
js/common.js      demo registry, chart helpers
js/demos.js       one demo per animated slide
data/*.js         generated, window.DATA
scripts/*.py      data generation
scripts/serve.py  no-cache local server
scripts/shots.py  headless screenshots
lib/              reveal, katex, d3, fonts
No bundler or npm: open index.html via scripts/serve.py. Generated data files are plain scripts that set window.DATA, so they also load from file:// without fetch.

Example: hydrogen 1s density in a Gaussian basis

exact: cusp at the nucleus
·
one Gaussian: no cusp
·
STO-3G: closer, still flat at $r=0$
·
log scale: tails decay as $e^{-\alpha r^2}$, not $e^{-2r}$
data: scripts/h1s_data.py
Single optimal Gaussian alpha = 8/(9 pi). STO-3G exponents and coefficients for H with zeta 1.24. The log view is the point of the slide: any finite Gaussian expansion decays too fast far from the nucleus.

Workflow

You design the figures, the agent builds them

1
Decide what each slide has to make obvious, and which figure or animation shows it best
2
Let the agent implement it: d3 code, data scripts, layout, screenshot checks
3
Review it as the audience will see it, and give concrete feedback per slide
# on the server, next to the agent
python3 scripts/serve.py 8000

# on your laptop, if the server is remote
ssh -L 8000:localhost:8000 server

# then open http://localhost:8000
Your time goes into what the audience should understand; the implementation is cheap now. Keep the slides plain: little text, one clear figure, details in the notes.
